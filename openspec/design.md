## Context

See proposal.md for motivation. Same constraints as the Go SDK (see the equivalent `go-sdk` change): hush-hush's `api/openapi.yaml` is spec-first, linted but not semantically drift-checked; no real API-version concept; auth is a static bearer token on write paths only, plus an optional unverified `X-Caller` header.

## Goals / Non-Goals

**Goals:**
- A deterministic, mechanically regenerable client.
- Idiomatic Python: both sync and async clients, type hints throughout, no bare `dict` payloads.
- A clear generated/hand-written boundary that survives regeneration.
- A regeneration pipeline that surfaces breaking spec changes via classification, even without gating merge.

**Non-Goals:**
- OAuth2 support — hush-hush only has a static bearer token.
- A unified cross-language docs site.
- Any change to hush-hush's server or its spec.
- Implementing Pact provider verification inside hush-hush's own CI.
- Automating the PyPI publish step — deliberately manual, tracked in hush-hush issue #76.

## Decisions

**Generator: `openapi-python-client`, not `openapi-generator`'s generic Python template or a hosted platform.** `openapi-python-client` produces modern, type-hinted `attrs`-based models and reads as idiomatic Python; `openapi-generator`'s Python output is dated (pre-type-hints style in places) and less consistent. Hosted platforms rejected project-wide in favor of free OSS tooling.

**Transport: `httpx`, giving one hand-written layer both sync and async clients.** `requests` has no async story; building two independent implementations (`requests` + `aiohttp`) would double the hand-written surface area for retry/auth/error logic. `httpx`'s matching sync/async APIs let a single implementation drive both `Client` and `AsyncClient` classes.

**Generated/hand-written boundary via header comment.** `openapi-python-client` emits its own package tree; the hand-written layer imports from it rather than editing it, and generated files carry `# Code generated by openapi-python-client; DO NOT EDIT.`. A CI check fails if a generated file's diff isn't purely mechanical regeneration output.

**Spec pinning via git submodule**, same approach as the Go SDK: the submodule's pinned commit is the version record; the generated package's `__init__.py` additionally states the pinned commit as a human-readable constant.

**Versioning via spec diff.** `openapi-diff` compares the current pinned commit against the one the last release was generated from and classifies the change as additive or breaking, driving the semver bump.

**Merge policy: full auto-merge for this session, scaffolding and all regeneration PRs alike** — an explicit, repeated grant from Ryan, given after being shown the risk that a breaking spec change can produce a small, green-CI-passing diff. The `openapi-diff` classification still runs and is surfaced on every PR for visibility; it doesn't gate merge.

**Auth: bearer token in the constructor with an `HUSH_HUSH_API_KEY` env var fallback; `X-Caller` as a per-call keyword argument, not client-level config.** Same reasoning as the Go SDK: the token is only required on write paths, and `X-Caller` attributes a specific call, not a client instance.

**Retry: network failures, 5xx, and 429 only; exponential backoff with jitter; honor `Retry-After`.** Never retry other 4xx.

**Errors: a typed exception hierarchy** (e.g. `HushHushError` base, `APIError` subclass) carrying status, an optional request-ID attribute (populated when a documented header is present, empty otherwise), and the parsed error body.

**Packaging: `uv`, not Poetry.** Corrected during implementation (2026-08-29): checking the org's actual current scaffold (`scaffold-python-cli`) rather than relying on CLAUDE.md's illustrative "npm / poetry / go mod" example shows `uv` is the real, current convention — Poetry was never a settled decision, just an unverified assumption. PyPI publish is a manual maintainer step, not CI-automated, per hush-hush issue #76.

## Risks / Trade-offs

- [`openapi-python-client` has no enforced custom-code region] → CI check on the generated package's diff shape catches an accidental hand-edit before merge.
- [A single `httpx`-based hand-written layer driving both sync and async clients is more complex than writing one] → still less total surface area than maintaining two independent client implementations, and matches what mature Python SDKs (e.g. OpenAI's, Anthropic's own) already do.
- [Full auto-merge applies to all regeneration PRs, so a breaking spec change can auto-merge as a small diff] → accepted risk, per Ryan's explicit repeated auto-merge grant. `openapi-diff`'s classification remains visible after the fact even though it doesn't block.
- [Floor corrected from 3.10+ to 3.11+ during implementation] → `openapi-python-client` 0.29.0 requires Python >=3.11; a generator that can't run on the floor version isn't a real constraint to hold to. 3.10 was going to reach EOL in October 2026 regardless, so this isn't a meaningful loss of reach.

## Open Questions

- Whether hush-hush's responses carry a request-ID header — if not, the exception's `request_id` attribute stays `None`; doesn't change the exception's shape.

Resolved during go-sdk implementation (2026-08-29), applies here too: the audit-log query has no pagination — checked directly against hush-hush's `api/openapi.yaml`. `/audit-log` takes only `object_id`/`caller`/`from`/`to` filters and returns a flat array. Both clients expose a single typed query method returning a list, not an iterator. The spec also documents a sixth operation, `GET /objects/{id}/used-by`, missed in the original proposal; it's included as a typed method alongside create/get/update/delete/audit-log.
